# 从 0 到 1：搭建可扩展的 QQ 群聊机器人

本文介绍如何基于 QQ 官方机器人开放平台和大模型 API，搭建一个可配置、便于扩展的群聊机器人。项目本身不绑定某个名字、性格或固定人设；机器人表现由 `config/persona.json` 配置。

## 一、整体工作流程

```text
① 群里有人 @ 聊天机器人
        ↓
② 腾讯官方服务器：转发给你的程序（WebSocket 长连接）
        ↓
③ 大脑层：你的程序给人设 + 聊天记录 → 发给大模型
        ↓
④ 大模型（DeepSeek 等）生成回复文字
        ↓
     回复发回群里
```

机器人程序负责连接 QQ、组织上下文、调用大模型并发送回复。模型负责根据收到的提示词和聊天记录生成文本。聊天记录、访问控制和提示词等行为由程序配置和管理。

### 大模型和机器人程序的分工

大模型本身不会连接 QQ，也不会自动保存不同会话的聊天记录。项目中的程序负责收消息、读取会话历史、构建提示词、调用模型、保存对话并回发结果。因此，替换机器人的名字和风格通常只需调整人设配置；更换平台或模型时，则由对应适配层处理。

## 二、项目的可扩展结构

当前项目采用模块化单体：在 Rock Pi 上作为一个 Python 服务运行，内部按职责分层。

```text
QQ 平台事件
    ↓
QQ 适配器：转换平台消息、发送平台回复
    ↓
应用核心：访问控制、限速、上下文与回复编排
    ├── 人设配置与场景触发器
    ├── LLM 调用
    └── SQLite 对话记忆
```

- `src/adapters/qq.py` 负责把 QQ 事件转换成统一消息格式。
- `src/app/` 保存平台无关的消息模型和处理流程。
- `src/llm.py` 封装 OpenAI 兼容的大模型 API 调用。
- `src/memory.py` 负责 SQLite 对话存储。
- `config/persona.json` 保存可更换的机器人名字、风格、规则和示例。
- `src/main.py` 加载配置并组装各部分，启动 QQ 机器人。

以后接入其他聊天平台时，可以新增对应适配器并复用应用核心。更换大模型时，可以替换或扩展模型调用实现。人设不是代码固定身份，而是独立配置。

## 三、准备账号和密钥

需要准备：

| 项目 | 用途 |
|---|---|
| QQ 开放平台机器人 | 接收群聊事件并发送回复 |
| 大模型 API Key | 让程序调用 DeepSeek 或其他兼容模型 |
| Python 环境 | 安装依赖并运行服务 |

请按 QQ 开放平台当前要求完成开发者注册和机器人创建。保存好 AppID 与 AppSecret。平台能力、审核和权限要求可能随时间变化，请以开放平台后台说明为准。

## 四、本地安装和配置

在项目根目录安装依赖：

```bash
python -m venv .venv
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
if (!(Test-Path .env)) { Copy-Item .env.example .env }
if (!(Test-Path config\persona.json)) { Copy-Item config\persona.example.json config\persona.json }
```

Linux：

```bash
source .venv/bin/activate
pip install -r requirements.txt
test -f .env || cp .env.example .env
test -f config/persona.json || cp config/persona.example.json config/persona.json
```

编辑 `.env`，填写机器人和模型服务配置：

```dotenv
BOT_APPID=你的机器人AppID
BOT_SECRET=你的机器人AppSecret
LLM_API_KEY=你的模型API密钥
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
DATA_DIR=./data
```

`.env` 只用于本地或服务器运行，不要提交到代码仓库，也不要把密钥贴到公开日志或问题中。若使用其他 OpenAI 兼容服务，按服务商文档修改 `LLM_BASE_URL`、`LLM_MODEL` 和 API Key。

`config/persona.example.json` 是人设模板，复制后生成的 `config/persona.json` 才会被程序读取。程序不会自动读取任何带 `.example` 后缀的文件；如果 `config/persona.json` 已经存在，请直接编辑它，不要再次覆盖。

## 五、先在命令行试聊

从项目根目录运行：

```bash
python src/cli_chat.py
```

命令行模式不连接 QQ，可用来检查模型连接和人设效果。输入 `退出`、`quit` 或 `exit` 结束。

也可以运行离线烟雾测试：

```bash
python src/smoke_test.py
```

它会向模型发送 5 条固定问题并打印回复，不连接 QQ，也不保存测试对话。每次运行会产生 5 次模型 API 请求，可能产生少量费用；它适合快速检查配置和回复方向，不会自动判断回答是否合格。

机器人风格由 `config/persona.json` 控制。你可以修改名称、规则、语气、示例对话和场景触发器。比如，将示例对话写成通用的角色：

```json
{
  "name": "群聊助手",
  "self_intro": "我是一个 AI 助手，可以陪大家聊天并协助处理问题。",
  "speaking_style": {
    "tone": "自然、友好、简洁",
    "default_examples": [
      {
        "user": "今天有点累",
        "bot": "辛苦啦。想聊聊发生了什么，还是想先换个轻松的话题？"
      }
    ]
  }
}
```

这是格式示例，具体字段请保持与项目现有 `config/persona.json` 的结构一致。提示词示例只决定机器人行为，不会改变 QQ 平台连接方式。

## 六、连接 QQ 群

命令行试聊正常后，在项目根目录启动正式机器人：

```bash
python src/main.py
```

该命令会以前台方式运行，终端需要保持打开；按 `Ctrl+C` 停止。若后续改用 systemd 管理，先停止这个前台进程，避免同一机器人重复启动。

确认 QQ 开放平台后台已配置应用所需的群聊能力，并将机器人添加到测试群。之后在群里 `@` 机器人发送消息，观察程序日志和回复。

当前程序订阅群聊消息，也配置了 C2C 私聊 intent。能否收到私聊事件还取决于 QQ 开放平台后台是否为该机器人开通相应权限。

## 七、调整提示词和回复风格

人设配置主要包括：

- `name`、`self_intro`：机器人名称和自我介绍；
- `core_rules`：应遵守的行为规则；
- `speaking_style`：语气、避免的风格和示例对话；
- `triggers`：特定关键词触发的补充提示。

编写提示词时，建议明确回复长度、口吻、边界和特定场景的处理方法，并提供少量高质量示例。触发器目前依赖关键词匹配，无法覆盖所有表达方式；涉及重要安全问题时，不应把关键词触发或模型提示词当作唯一保障。

## 八、记忆、会话和数据目录

SQLite 数据库默认保存在 `data/memory.db`，可通过 `.env` 中的 `DATA_DIR` 指定其他目录。机器人给模型发送上下文时，默认读取同一会话最近 8 轮对话。

会话按平台、会话类型、会话 ID 和用户 ID 隔离，避免不同群聊之间混用历史。数据库包含用户聊天内容，应限制文件访问权限，并在升级或迁移前做好备份。更换 `DATA_DIR` 不会自动搬运旧数据库。

## 九、常见问题

| 现象 | 常见原因 | 检查方向 |
|---|---|---|
| 命令行试聊报 API 错误 | API Key、模型名称或服务地址不正确 | 检查 `.env` 和模型服务商配置 |
| QQ 群里没有回复 | 程序未运行、机器人未进群或平台权限未配置 | 查看终端日志和开放平台后台 |
| C2C 私聊没有事件 | 机器人类型或开放平台未开通私聊权限 | 检查后台权限；代码 intent 不能代替平台授权 |
| 回复没有预期风格 | 人设规则或示例不够明确 | 调整 `config/persona.json` 后重新试聊 |
| 对话记忆没有保留 | 数据目录变化或数据库文件不可写 | 检查 `DATA_DIR` 和文件权限 |
